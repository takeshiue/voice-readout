# Codexで使う

このリポジトリは、既存のClaude Codeプラグインと独立したCodexプラグイン定義も含む。Claude Codeは従来の`hooks/hooks.json`を読み、Codexは`.codex-plugin/plugin.json`から`hooks/codex-hooks.json`だけを読む。そのため、Codex対応を有効にしてもClaude Codeのフック構成は変わらない。

Codexのプラグインディレクトリでこのプラグインを有効にしたあと、最初に`/hooks`を開き、voice-readoutのフックを確認して信頼する。Codexは未管理のコマンドフックを、確認されるまで実行しない。

## 読み上げるタイミング

- `SessionStart`：新規開始・再開時に挨拶し、緊急停止ボタンを通知へ出す。
- `Stop`：応答完了時に本文を読む。フルモードでは本文を、要約モードでは追加のAIプロセスを起動せず先頭の自然な区切りまでを読む。
- `SessionEnd`：終了時に挨拶し、停止ボタンの通知を片付ける。

Codexでは実行許可の音声は出さない。`PermissionRequest` は自動レビューや既存許可による自動承認より前にも発火し、フック入力には「最終的に人の操作を待つか」を示す値がないため、ここで音を出すと誤って「実行許可を求めています」と伝えてしまう。入力待ちの視覚通知はCodex本体のTUI通知を使う。

## 設計上の違い

Claude Codeの要約モードは、従来どおり`claude --safe-mode -p --model haiku`を使う。Codex版では応答ごとに`codex exec`を起動しない。待ち時間、利用量、再帰フックの問題を避け、まずは確実に聞こえる短縮読み上げを既定とするためである。

本文の整形ロジックは`bin/response-text.sh`にあり、CodexとClaudeの両方がこれを読み込む。同じ整形規則の写しが2か所にあると、片方だけ直したときにもう片方が黙って古いままになるためである。共有するのは整形規則だけで、Claudeの要約実行方式・既定値・フック定義は変えていない。

`SessionStart`は`bin/session-start.sh`を両ホストで共有する。常駐通知の投稿と最初の読み上げが同時にTermux:APIへ要求を出すと、停止ボタンの表示が大きく遅れることがあったため、通知を先に投げ、挨拶はその完了を短く（既定8秒、`START_NOTIFY_WAIT_SECS`）待ってから話し始める。

## 設定と停止

音声エンジン、話速、フル／要約モード、故障復旧は既存の音声基盤を使う。Codexのフック実行中はCodexプラグインのデータ領域を使うため、Claude Codeの設定ファイルを変更しない。

Android通知の緊急停止ボタンだけは共通である。端末で鳴っている読み上げを、どちらのホストから始まったかを問わず止めるためである。
