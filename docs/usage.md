## チャットで切り替える

すべてチャットで「〜して」と頼むだけで切り替わる（裏で `bin/toggle.sh` が実行される）。設定は端末側のデータディレクトリ（`${CLAUDE_PLUGIN_DATA}`、無い場合は `~/.claude/plugins/data/voice-readout-voice-readout/`）の `voice-readout-config` に保存され、次回以降のセッションにも引き継がれる。

| 頼み方の例 | 効果 |
|---|---|
| 「音声読み上げをオフにして」 | 応答の読み上げ・許可確認の読み上げを両方オフ |
| 「音声読み上げをオンに戻して」 | 両方オン |
| 「応答の読み上げだけオフにして」 | 応答終了時の読み上げのみオフ（許可確認は継続） |
| 「許可確認の読み上げだけオフにして」 | 許可確認・入力待ちの読み上げのみオフ（応答読み上げは継続） |
| 「フル読み上げにして」 | 要約せず、コードを除いた本文をそのまま読む |
| 「要約読み上げに戻して」 | 一文要約に戻す（デフォルト） |
| 「読み上げを1.3倍にして」 | 話速の指標を変更（裏で `toggle.sh speed 1.3`。全エンジンに効く。1.0＝毎分約300字、既定1.2、範囲0.5〜2.0） |
| 「もう少しゆっくり読んで」 | 同じく指標を下げる |
| 「起動の挨拶をオフにして」 | セッション開始時の挨拶読み上げをオフ（裏で `toggle.sh greeting off`。応答・許可確認の読み上げとは独立） |
| 「起動の挨拶を『〜』にして」 | 挨拶の文言を変更（裏で `toggle.sh tune STARTUP_GREETING_TEXT <文言>`） |
| 「終わりの挨拶をオフにして」 | セッション終了時の挨拶クリップをオフ（裏で `toggle.sh farewell off`） |
| 「Gemini の TTS に切り替えて」（要 API キー） | **全機能の既定**を Gemini API TTS に切替（個別に上書きしていない機能すべてに効く） |
| 「Inworld の TTS に切り替えて」（要 API キー） | **全機能の既定**を Inworld Realtime TTS に切替 |
| 「ElevenLabs の TTS に切り替えて」（要 API キー） | **全機能の既定**を ElevenLabs に切替 |
| 「オンデバイスの読み上げに戻して」 | 全機能の既定を Android 標準 TTS（Termux:API 経由）に戻す（デフォルト） |
| 「フルの読み上げだけ Inworld にして」（等） | **その機能だけ**エンジンを上書き（裏で `toggle.sh backend-<機能>`） |
| 「ハイブリッドをオンにして」 | **フル ハイブリッド**：フル読み上げ＋クラウド音声のとき、出だしだけオンデバイスで即座に喋り出し、途中でクラウド音声に交代する（裏で `toggle.sh hybrid on`。既定オフ。仕組みは [設計ノート](design.md#フル-ハイブリッド出だしはオンデバイス続きはクラウド)） |
| 「チャンクマーカーをオンにして」 | クラウド読み上げの継ぎ目にキュー音を鳴らす確認用モード（裏で `toggle.sh chunk-marker on`。既定オフ。詳細は [設計ノート](design.md#クラウド読み上げのチャンク再生と継ぎ目マーカー)） |
| 「校正をやり直して」 | 継ぎ目の自動校正（`CLOUD_PLAY_LEAD`）をやり直す（裏で `toggle.sh recalibrate`） |

API キーの登録だけは例外で、**チャットではなくターミナルで**行う（会話に書いた内容はトランスクリプトとして端末に保存され、モデルへの入力としても送られるため）。手順は [設計ノート](design.md#読み上げエンジンバックエンドの仕組み) を参照。

## モードの違い（要約／フル）

| | 要約モード（デフォルト） | フル読み上げモード |
|---|---|---|
| 内容 | Haiku が一文に要約 | 本文をほぼそのまま（コード・URL・Markdown記号は除去） |
| 向いている場面 | 短時間でテンポよく状況を把握したい | 要約だと何を言われているか分かりにくいとき、正確に内容を追いたいとき |
| 読み上げ時間 | 数秒〜十数秒 | 内容量に応じて数十秒〜数分（背景処理なので操作はブロックしない） |

## 読み上げエンジンを選ぶ

読み上げエンジンは**4つの機能ごとに独立して選べる**。

| 機能 | 何を読むか | 設定キー |
|---|---|---|
| 通知 | 許可確認・入力待ち | `TTS_BACKEND_NOTIFICATION` |
| 要約 | 応答を一文に要約 | `TTS_BACKEND_SUMMARY` |
| フル読み上げ | 応答をほぼそのまま | `TTS_BACKEND_FULL` |
| ファイル読み上げ | `speak-text.sh` に渡した文章 | `TTS_BACKEND_FILE` |

「Gemini に切り替えて」のような指定は全機能共通の既定（`TTS_BACKEND`）を変え、「通知だけオンデバイスのままにして」のような指定はその機能だけを上書きする。既定は4機能とも「オンデバイス」で、これは追加設定なし・オフラインで動く。

クラウド系（Gemini／Inworld／ElevenLabs）は API キーの登録が要る。エンジンごとの違い・費用・キーの登録手順は [設計ノート](design.md#読み上げエンジンバックエンドの仕組み)。

## ステータスライン

「次の応答は喋るのか、黙るのか」を毎回チャットで訊かずに済むよう、Claude Code のコンソール最下部に現在の状態を1行で表示できる。

**インストール後、最初に Claude Code を起動したときに自動で登録され、その起動のうちに出る。** 何もしなくてよい（この自動登録は1インストールにつき1回だけ。自分で消した場合は消えたまま復活しない）。プラグインを入れた**そのセッションには出ない**——フックは起動時に読み込まれるため、「入れる → 起動し直す → 出る」で起動が1回挟まる。

手で操作したいときは次を実行する。チャットで「ステータスラインを出して」と頼んだ場合も同じものが動く：

```sh
bash <プラグイン>/bin/statusline.sh --install     # 登録
bash <プラグイン>/bin/statusline.sh --uninstall   # 解除
```

`~/.claude/settings.json`（＝個人設定）に、スクリプト自身の絶対パスが書き込まれる。**パスを人が打つ必要はない。** 反映に再起動は要らない（Claude Code は設定ファイルを監視していて、次にやり取りしたときの再描画から出る）。既に別のスクリプトが登録されていれば奪わずに中止する（置き換えるなら `--force`）。自動登録・自動修復の仕掛けは [設計ノート](design.md#ステータスラインの自動登録と自動修復)。

表示はこうなる：

```
voice readout | greet 🔊🔊 | notif 🔊 local | resp 🔊 sum gemini | ×1.2 | 🔔
```

**この行に出るものはすべて、その場で切り替えられる**（表示専用の項目はない）。

| 区画 | 意味 | 設定キー | 変え方（チャット／コマンド） |
|---|---|---|---|
| `greet` の左 🔊 | **起動**の挨拶 | `STARTUP_GREETING` | 「起動の挨拶をオフにして」／`toggle.sh greeting off` |
| `greet` の右 🔊 | **終了**の挨拶 | `SESSION_END_GREETING` | 「終わりの挨拶をオフにして」／`toggle.sh farewell off` |
| `notif` の 🔊 | 許可確認・入力待ちの読み上げ | `NOTIFICATION_READOUT` | 「許可確認の読み上げだけオフにして」／`toggle.sh notification off` |
| `notif` のエンジン名 | 通知に使うエンジン | `TTS_BACKEND_NOTIFICATION` | 「通知だけ Inworld にして」／`toggle.sh backend-notification inworld` |
| `resp` の 🔊 | 応答の読み上げ | `STOP_READOUT` | 「応答の読み上げだけオフにして」／`toggle.sh stop off` |
| `resp` の `sum`／`full` | 要約モードか全文モードか | `READOUT_MODE` | 「フル読み上げにして」／`toggle.sh mode full` |
| `resp` の `hyb` | フル ハイブリッドが実際に効く条件が揃っている | `HYBRID_TTS` | 「ハイブリッドをオフにして」／`toggle.sh hybrid off` |
| `resp` のエンジン名 | そのモードで使うエンジン | `TTS_BACKEND_SUMMARY`／`_FULL` | 「要約だけ Gemini にして」／`toggle.sh backend-summary gemini` |
| `×1.2` | 話速の指標（1.0＝毎分約300字。どのエンジンで喋っていても同じ意味） | `READOUT_SPEED` | 「読み上げを1.3倍にして」／`toggle.sh speed 1.3` |
| `🔔` | チャンク区切りマーカー（on のときだけ表示） | `CHUNK_MARKER` | 「チャンクマーカーをオンにして」／`toggle.sh chunk-marker on` |
| `🛑 ALL MUTED` | ストップスイッチが押されている（他の表示は出さない。トグルが on でも鳴らないため） | ― （設定ファイルではなく固定パスのファイル） | 通知の［再開］ボタン／`readout-switch.sh resume` |

挨拶にエンジン名が付かないのは、挨拶が固定クリップまたは起動確認用の生 TTS で、機能別のエンジン選択を持たないため。両方のトグルをまとめて変える「音声読み上げをオフにして」（`toggle.sh all off`）は `notif` と `resp` の2つに効き、挨拶には効かない。

アイコンは 🔊＝オン、🔇＝オフ。エンジン名は狭い画面に収めるため表示だけ短くしてある（**設定値そのものは従来どおり**）：

| 表示 | 設定値 |
|---|---|
| `local` | `ondevice`（端末内で合成。ネットワーク不要） |
| `gemini` | `gemini` |
| `inworld` | `inworld` |
| `11labs` | `elevenlabs` |

この行はフックとまったく同じ config ファイル・同じストップスイッチのパスを読むので、**表示と実際に鳴るかどうかが食い違うことはない**。

## 挨拶（起動時・終了時）

- **起動時**（`SessionStart`）：短い挨拶を一度読み上げる。既定の文言は「ボイスリードアウト、準備できたよ」。鳴れば正常、鳴らなければエンジンが固まっている——**動作確認を兼ねている**ので、通常の読み上げと同じ経路を通す。新規起動と再開（`claude --resume`/`--continue`）のときだけ鳴り、`/clear` や自動要約後の再開では鳴らない。
- **終了時**（`SessionEnd`）：事前録音クリップ「お疲れ様。またね。」を一度再生する。`/clear`（同じセッションの再起動）では鳴らない。
- どちらも `STARTUP_GREETING` / `SESSION_END_GREETING`（既定 on）で個別にオフにできる。応答・許可確認の読み上げとは独立していて、「音声読み上げを全部オフにして」では止まらない。
- ストップスイッチが入っていれば、どちらも鳴らない。

文言を差し替えるときは**製品名をカタカナで書く**こと——英字の `voice-readout` を渡すと TTS が「レッドアウト」と読む。終了クリップの差し替えは `assets/session-end.wav` を置き換えるだけ。理由と録音レシピは [設計ノート](design.md#決まり文句の事前録音音声)。

## 声が聞こえないとき

1. スマホに ⚠️ 通知が届く（①Termux:API → ②Google音声の順、頻発防止のため 30 分に一度まで）
2. 通知（または「設定画面を開く」ボタン）をタップして開いた画面で「強制停止」を押す
3. 直らなければ②の通知でも同様に強制停止
4. 裏の自動復旧ウォッチャーが読み上げの復活を検知すると「直ったみたいよ」と声で知らせ、通知を自動で消す

この順序（Termux:API を先に止める）には理由がある → [設計ノート](design.md#termuxapi-との関係)

## ストップスイッチ（確実に黙らせる）

読み上げが暴走しているとき、他のどの仕組みよりも確実に効く独立したスイッチ。**設定も環境変数も Claude も一切経由しない**（[理由](design.md#ストップスイッチが設定を一切見ない理由)）。

実際には、スマホの通知に常駐する1枚のボタンで切り替えるのが基本。1枚の通知が状態とアクションを兼ねていて、「読み上げ 有効」＋［停止］⇄「読み上げ 停止中」＋［再開］とトグルする。

ターミナルからなら：

```
readout-switch.sh stop     # 全読み上げを停止する
readout-switch.sh resume   # 読み上げを再開する
readout-switch.sh status   # 現在の状態を表示
readout-switch.sh notify   # 状態通知を出し直す
```

**いま喋っているチャンクは必ず最後まで鳴る。** 停止は次のチャンクの直前で効き、残りを破棄する。

## 調整値（config ファイル）

オン/オフ・モード・バックエンドに加えて、動作の細かな調整値もすべて同じ config ファイル（データディレクトリの `voice-readout-config`）に集約されている。`toggle.sh init` が既定値で書き出すので、何が変えられるかはファイルを見れば分かる。変更は `toggle.sh tune <KEY> <VALUE>`（またはファイルを直接編集）。同名の環境変数 `VOICE_READOUT_<KEY>` を付ければ、その1回だけ config より優先される。

**普通は触らなくてよい。** 以下は、聞いていて気になる点があったときに引く表。

### 読み上げ全般

| KEY | 既定 | 意味 |
|---|---|---|
| `READOUT_SPEED` | 1.2 | **全エンジン共通の話速指標**（1.0＝毎分約300字）。下の速度キーはこれから自動算出される |
| `TTS_RATE` | auto | オンデバイスの速度（`auto`＝指標から算出。数値を書けばそのエンジンだけ上書き） |
| `GEMINI_SPEED` | auto | Gemini の速度（同上） |
| `INWORLD_SPEAKING_RATE` | auto | Inworld の速度（同上） |
| `ELEVENLABS_ATEMPO` | auto | ElevenLabs の速度（生成後に ffmpeg で加工。同上） |
| `TTS_PITCH` | 1.0 | ピッチ（オンデバイスのみ） |
| `CHUNK_MARKER` | off | 継ぎ目にキュー音を鳴らす確認用モード |

### オンデバイス

| KEY | 既定 | 意味 |
|---|---|---|
| `ONDEVICE_MAX_CHARS` | 240 | 1回あたり文字数上限（超過で要約に劣化。[理由](design.md#オンデバイス読み上げの長さ制限)） |
| `TTS_CHUNK_CHARS` | 150 | チャンク長（1回の発話ごとに立ち上がりがかかるので、短くするほど文の途中の無音が増える） |
| `TTS_CHUNK_RETRIES` | 4 | チャンクごとの再試行回数 |
| `TTS_RETRY_WAIT_BASE` | 20 | 再試行の待機ベース秒（線形バックオフ） |
| `TTS_RETRY_WAIT` | 90 | 再試行の待機上限秒 |
| `PREFLIGHT_TIMEOUT` | 10 | エンジン応答確認のタイムアウト秒 |
| `WARM_SKIP_WINDOW` | 120 | 直前の読み上げ成功からこの秒数以内なら、エンジン応答確認（約2秒）を省く。0 で無効 |
| `ONDEVICE_START_SECS` | 4.6 | 発話1回あたりの固定の立ち上がり秒（所要時間の見積りに使う） |
| `ONDEVICE_CHARS_PER_SEC` | 5.0 | 1秒あたりの読み上げ文字数（同上）。この2つは端末が遅い/速いときに引き直す |

### クラウド（Gemini／Inworld／ElevenLabs）

「エンジンの性質」を表すキーは `KEY_<エンジン名>`（例 `CLOUD_SECOND_CHUNK_CHARS_GEMINI`）の形でエンジン別に持てる。優先順位は `KEY_<エンジン名>` ＞ `KEY` ＞ 内蔵の既定値。

| KEY | 既定 | 意味 |
|---|---|---|
| `CLOUD_FIRST_CHUNK_CHARS` | 80 | 1つ目のチャンク長（短いほど喋り出しが早い） |
| `CLOUD_SECOND_CHUNK_CHARS` | 120（gemini は 200） | 2つ目のチャンク長。ここだけ生成が間に合いにくい |
| `CLOUD_CHUNK_CHARS` | 200 | 3つ目以降のチャンク長（長いほど継ぎ目の回数が減る） |
| `CLOUD_PLAY_LEAD` | auto | 次のチャンクを何秒早くかぶせるか。`auto` はこの端末で実測して自動決定（[仕組み](design.md#cloud_play_lead-の自動校正)）。数値を書けば学習せずその値を使う |
| `CLOUD_PLAY_LEAD_SAMPLES` | 24 | 自動校正が確定するまでに集める継ぎ目のサンプル数 |
| `CLOUD_HTTP_TIMEOUT` | 45 | API 呼び出しのタイムアウト秒 |
| `CLOUD_MIN_AUDIO_RATIO` | 0.65 | 返ってきた音声が「テキストを読み切るには短すぎる」と判定する比率。下回ると1回だけ生成し直す |
| `GEMINI_MODEL` | gemini-2.5-flash-preview-tts | 使用モデル |
| `INWORLD_MODEL` | inworld-tts-1.5-mini | 使用モデル |
| `ELEVENLABS_MODEL` | eleven_flash_v2_5 | 使用モデル（`eleven_v3` は表現力が高い代わりに速度指定が効かない） |
| `ELEVENLABS_SPEED` | ― | API 側の速度指定（0.7〜1.2。`eleven_v3` では効かないので通常は `ELEVENLABS_ATEMPO` を使う） |
| `ELEVENLABS_GAIN` | 1.0 | 音量倍率（他エンジンと音量を揃えるため） |

### フル ハイブリッド

仕組みは [設計ノート](design.md#フル-ハイブリッド出だしはオンデバイス続きはクラウド)。

| KEY | 既定 | 意味 |
|---|---|---|
| `HYBRID_TTS` | off | フル ハイブリッドの on/off（フル読み上げ＋クラウド音声のときだけ効く） |
| `HYBRID_UNIT_CHARS` | 60 | オンデバイス側の1単位＝**交代の粒度** |
| `HYBRID_MIN_ONDEVICE_CHARS` | 0（gemini は 60） | 最低これだけはオンデバイスで読む（1本目の生成が遅いエンジン向けの助走） |
| `HYBRID_MAX_ONDEVICE_CHARS` | 240 | オンデバイスで読んだ累計がこれを超えたら、読み進めるのをやめてクラウドを待つ |
| `HYBRID_SPECULATION` | 1 | 交代候補を同時にいくつ先行生成するか |
| `HYBRID_PREGEN_CHUNKS` | 2（gemini は 3） | 交代後のクラウド側を何チャンク先まで作り置くか |
| `HYBRID_PREPLAY_LEAD` | 1.0 | オンデバイスの声が終わる何秒前にクラウド音声の再生を始めるか（[継ぎ目の先読み](design.md#オンデバイスからクラウドへの継ぎ目を先読みで隠す)） |
| `HYBRID_PREPLAY_MAX_IDLE` | 600 | 直前の発話からこの秒数以上空いていたら先読みしない（端末が寝ていると所要時間の見積りが外れるため） |

### 長文パイプライン・その他

| KEY | 既定 | 意味 |
|---|---|---|
| `OVERFLOW_PIPELINE` | off | 長文時に「冒頭を先に読み、裏で全体を要約する」パイプライン（[仕組み](design.md#長文パイプライン冒頭を先に読み裏で要約する)） |
| `OVERFLOW_OPENING_CHARS` | 150 | そのパイプラインで先に読む冒頭の文字数 |
| `NOTIFY_COOLDOWN` | 1800 | 故障通知のクールダウン秒 |
| `WATCH_INTERVAL` | 120 | 復旧ウォッチャーの probe 間隔秒 |
| `LOG_MAX_BYTES` | 1048576 | ログ自動ローテーションの閾値バイト（**1世代あたり**。2世代で最大この2倍まで使う） |
| `STARTUP_GREETING` / `_TEXT` | on / ボイスリードアウト、準備できたよ | 起動時の挨拶と文言。**製品名はカタカナで書く** |
| `SESSION_END_GREETING` / `_TEXT` | on / ボイスリードアウト、またね | 終了時の挨拶と、画面に表示する文言（音声は固定クリップ） |

## 音声の一時ファイルを消す

`~/.voice-readout-tmp/` は読み上げのたびに音声ファイルを置く場所で、**チャンク音声（`vr-*`）以外は自動削除されない**ため使っているうちに溜まる（十数MBになることがある）。アンインストールせず容量だけ空けたいときは、ここを消せばよい。次の読み上げで必要なものは作り直される。

```sh
rm -rf ~/.voice-readout-tmp/
```
