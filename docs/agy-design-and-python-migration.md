# 設計・アーキテクチャ判断記録 (ADR): agy 対応および Python 一本化ロードマップ

## 1. 背景と目的

- **現在の状況**:
  - `voice-readout` は Claude CLI (Android/Termux), Codex (Android/Termux), および Windows 版 Claude Code (開発中) をサポート。
  - スクリプト構成は Android 向けの Bash (`.sh`) と Windows 向けの PowerShell (`.ps1`) に分かれている。
- **今回の目的**:
  - Antigravity CLI (`agy`) に音声読み上げ機能を搭載する（まずは Android / Termux 環境）。
  - 近い将来予定されている **「Windows 環境での `agy` 音声読み上げ対応」** および他環境への展開をスムーズに行える設計とする。

---

## 2. 課題と検討事項

1. **Windows における Bash 依存のリスク**:
   - Windows 環境では Bash (`.sh`) はネイティブではなく、Git Bash 等の特定シェル環境が必要となる。
   - 配布性・インストール手順・OS ごとのスクリプト（Bash / PowerShell）の二重管理コストが高い。
2. **Python の利点**:
   - Windows, Android (Termux), Linux, macOS のすべてで標準的・容易に動作する。
   - `transcript.jsonl` や複雑な JSON ログのパース、マークダウンのテキスト正規化、エラーハンドリングが堅牢に書ける。
   - Antigravity Python SDK や将来の拡張（MCP 等）との親和性が高い。

## 7. 実測ベンチマークとチャンク文字数（90文字基準）および段階的ランプアップ設計

### 7.1 実測ベンチマークと「90文字の黄金比」
実測測定（30文字〜180文字、および70〜130文字の10文字刻み）により、Gemini TTS API における文字数と生成時間・再生時間の関係が判明：

| 文字数 | 実測 生成時間 (`gen`) | 音声 再生時間 (`aud`) | 余裕度 (`aud` - `gen`) | 判定 |
| :---: | :---: | :---: | :---: | :--- |
| 60〜70文字 | 10.13秒 | 8.86秒 | -1.28秒 | 赤字（固定オーバーヘッド影響） |
| 80文字 | 12.03秒 | 11.43秒 | -0.60秒 | ほぼ均衡 |
| **★ 90〜95文字** | **12.17秒** | **13.57秒** | **+1.41秒** | **黒字（完全自走スイートスポット）** |
| 110文字 | 16.78秒 | 16.00秒 | -0.78秒 | 赤字 |
| 120文字 | 20.41秒 | 17.29秒 | -3.12秒 | 危険 |
| 130文字以上 | 28.11秒〜 | 19.14秒 | -8.96秒 | 完全アンダーラン（音途切れ） |

- **結論**: `TTS_CHUNK_CHARS = 90` を正式基準値として採用。

### 7.2 段階的ランプアップ（助走 ➡ 定常自走）のパイプライン設計
- **冒頭ローカル**: 80〜100文字（約16〜20秒発声）で大きな初期貯金を構築。
- **チャンク0 (第1助走)**: 約50〜60文字（生成約8〜9秒 ➡ ローカル発声中に確実に完成し、先行キック Pre-play が100%発動）。
- **チャンク1 (第2助走)**: 約70〜80文字（生成約10〜11秒 ➡ チャンク0再生中に完成）。
- **チャンク2以降 (定常自走)**: **90文字**（再生13.5秒 ＞ 生成12.1秒）で途切れなく安定巡航。

### 7.3 音声無音テール相殺（前倒しオーバーラップ補正）
- TTS エンジン特有の無音テール（約0.3〜0.45秒）を相殺するため、先行キック（`HYBRID_PREPLAY_LEAD=1.5`、`CLOUD_PLAY_LEAD=2.85`）を適用。
- これにより、人間の耳に届く真の無音間隔が **ジャスト 0.4〜0.5 秒の上品な息継ぎ** に着地する。

## 3. 下された設計判断 (Decision)

### 方針: 「段階的な Python 一本化 (クロスプラットフォーム共通化)」

全体を一気に書き換えるのではなく、今回の `agy` 対応を契機として **テキスト処理・データ抽出・将来の TTS コアロジックを Python モジュールとして部品化** し、段階的に Python へ統合していく。

```text
【Phase 1: 今回 (Android/Termux agy 対応)】
  - agy フック受付 (Bash/JSON) ──> 即座に {} 返却して非同期ワーカー起動
  - データ抽出・整形 (Python)  ──> transcript.jsonl パース、テキスト正規化
  - 音声再生・停止ボタン (Bash) ──> 既存の tts-lib.sh (Termux API / 停止スイッチ) を再利用

【Phase 2: Windows agy 対応 & TTS コア移植】
  - Python モジュールに OS 判定・TTS バックエンド (Windows SAPI / Android Termux / クラウド TTS) を組み込み
  - Windows 環境での agy 読み上げを同一の Python コアで実現

【Phase 3: 完全 Python 統一】
  - Claude / Codex / agy 全てのフックから直接 Python スクリプトを実行可能にする
  - OS / CLI 依存を最小化し、クロスプラットフォーム配布を容易にする
```

---

## 4. 今回（Phase 1）の実装スコープ

1. **Python コア (`bin/agy_readout.py` 等)**:
   - `agy` の `Stop` イベント等から `transcriptPath` を安全に読み取り、最後のメッセージを抽出。
   - コードブロックやマークダウン記号の除去、読み上げ用テキストの整形。
   - 将来 Windows SAPI や他 TTS バックエンドへ直接ディスパッチできるようにインターフェースを設計。
2. **フック呼び出しスクリプト (`bin/agy-*.sh`)**:
   - `agy` の同期フック要件を満たすため、JSON `{}` を即座に返して `setsid` でバックグラウンド実行。
   - 抽出したテキストを既存の `tts-lib.sh` 経由で Android Termux TTS に渡す。
3. **設定ファイル (`hooks/agy-hooks.json` 等)**:
   - `agy` の `.agents/hooks.json` やグローバル設定に登録できる定義。

---

## 5. 今後の展開（Windows agy 対応時のチェックポイント）

- `bin/agy_readout.py` が Windows（PowerShell / cmd）から直接呼ばれた場合でも動作するように、パス区切り文字（`os.path` / `pathlib`）やエンコーディング（UTF-8）に配慮して実装すること。
- Windows の TTS（SAPI や PowerShell 停止ボタン）への切り替え口を Python 内に抽象化して用意しておくこと。

## 6. 応答開始フィラー（30パターン）による初期遅延ゼロ化アーキテクチャ

### 課題
AI の回答完了（`Stop` フック発火）から、Android Termux TTS やクラウド TTS が実際にスピーカーから音を出し始めるまでに約 0.6〜0.9 秒のハードウェア・プロセス遅延が存在する。

### 解決策
AI 生成完了の瞬間に、**0.6〜0.9秒（3〜7文字）の事前録音フィラー音声（30パターン）からランダムに 1 つを 0.05 秒で即座に再生** する。
この 0.8 秒の間に裏で本編 TTS のプロセス起動・バッファリングが完了するため、**ユーザーの体感待ち時間を完全に 0 秒（自然な会話の間）に置換** する。

### フィラー音声リスト（全30パターン）
- **A. お待たせしました／できました系 (8種)**: 「お待たせしました」「大変お待たせしました」「お待たせっ」「お待たせいたしました」「お待たせ、できたよ」「準備ができました」「まとまりました」「できましたよ」
- **B. 思考・会話クッション系 (8種)**: 「えっとですね…」「ええと…」「そうですね…」「うーん、そうですね」「ええ、そうですね」「なるほどですね」「はい、えーっと…」「えっと、こちらはですね」
- **C. それでは説明・お答えします系 (8種)**: 「それではお答えします」「お答えしますね」「回答いたします」「ご説明しますね」「内容をお伝えします」「お伝えしますね」「結果をお話しします」「はい、お答えします」
- **D. 導入・読み上げ開始系 (6種)**: 「では、読み上げます」「それでは参ります」「では、いきますね」「結果はこちらです」「回答はこちらです」「内容はこちらです」
