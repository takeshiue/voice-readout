# ハイブリッド引き継ぎのエンジン別調整

ローカル音声（Windows は SAPI）で冒頭を読み、クラウド音声の生成が終わり次第
引き継ぐ機能（`HYBRID_TTS`）の調整記録。2026-08-15 に Windows 対応を入れた際の
実測値とその根拠を残す。

## 調整の考え方

引き継ぎが成功する条件は **「ローカル音声を喋っている時間 ≧ クラウドの生成時間」**。
足りないとローカルで次のユニットを読み始めてしまい、間に合うまでこれを繰り返す。

判定は**ローカル音声が呼ばれた回数**で行う。正常なら 1 回。

- 1 回 → 1 ユニットで引き継げた（適正）
- 2 回以上 → 生成が間に合わず繋ぎ続けている（ローカル長が不足）

回数はログの `windows-sapi` の出現数で数えられる。`CHUNK_MARKER=on` にすると
ローカル音声の読み終わりごとに区切り音が鳴るので、耳でも数えられる
（Windows のみ。`_play_chunk_marker`）。

## SAPI の読み上げ速度（Windows、実測 2026-08-15）

```
105 字 → 14.1 秒   ≒ 7.4 字/秒、起動 0.3 秒
```

Android の `termux-tts-speak` は 5.0 字/秒・起動 4.6 秒で、値が違う。
`_ondevice_speech_secs()` がプラットフォームで既定値を分けている。

必要なローカル長は次式で求める。**平均ではなく最大**を使う。平均で合わせると
生成が遅い回に引き継ぎが落ちる。

```
必要な字数 = クラウド生成時間の最大値 × 7.4 + 余裕 5 字
```

## エンジン別の設定値

キーは `HYBRID_MIN_ONDEVICE_CHARS_<ENGINE>`（大文字）。

**この表は Windows / SAPI の値。** Android は読み上げ速度が違う（5.0 字/秒・
起動 4.6 秒）ため、同じ字数が別の秒数になる。そのまま持ち込めない。

| エンジン | 生成 平均 | 95% 点 | 最大 | 設定値 | 状態 |
|---|---|---|---|---|---|
| ElevenLabs | 8.7 秒 (44 件) | 11.1 秒 | 15.8 秒 | **120 字** | 確定（5/5 成功） |
| Gemini | 11.8 秒 (24 件) | — | 17.0 秒 | 130 字 | 暫定・**要検証** |
| Inworld | 未測定 | — | 未測定 | 未設定 | **要測定** |
| Fish Audio | 測定不能 | — | 測定不能 | 未設定 | **課金要**（HTTP 402） |

### ElevenLabs = 120 字の根拠（2026-08-15 確定）

`tests/find-hybrid-length.sh` で二分探索し、境界を挟み込んで求めた。

```
bracket  200字 PASS / 40字 FAIL     ← 探索前に両端を検証
round 1  [40,200] 120字 PASS
round 2  [40,120]  80字 PASS
round 3  [40, 80]  60字 PASS
round 4  [40, 60]  50字 FAIL
境界: 50字(FAIL) 〜 60字(PASS)
```

境界は 60 字だが、**採用値は 120 字**。理由は生成時間のばらつき。探索中に
15.8 秒という回が出ており、60 字（8.4 秒）では覆えない。全 44 件を集計すると

```
平均 8.7 / 95% 点 11.1 / 最大 15.8 秒
→ 95% 点なら 79 字、最大値なら 114 字
```

95% 点で合わせると 20 回に 1 回失敗するため、最大値を覆う 114 字に丸めて
120 字（16.5 秒）とした。この値で 5 回連続成功を確認済み。

**境界をそのまま採用しない**のはこのため。境界は「最も遅い生成にちょうど届く
長さ」であり、それより遅い回は普通に起きる。短すぎる代償は余分なローカル読み
上げ（区切り音が 2 回鳴る）、長すぎる代償はローカル音声が数秒伸びるだけなので、
非対称な誤差として長い側に振る。

## 残タスク

### Gemini（2026-08-16 09:00 以降）

無料枠が日次 100 リクエストで、2026-08-15 に調整計測で使い切った。
API の応答は `Please retry in 15h11m56s`（17:47 時点）。

- [ ] 130 字で引き継ぎが 1 回で済むか確認する
- [ ] 足りなければ 150 字前後まで上げて再測定する

計測は 1 回の読み上げで 3〜5 リクエストを消費する。100 件では反復計測の
余裕が少ないので、1 回で判断できるよう短めのテキストで測る。

### Inworld

- [ ] chunk0 の生成時間を数回測る
- [ ] 最大値から必要な字数を算出して設定する

### Fish Audio

HTTP 402（`s2.1-pro-free` の無料枠が廃止、または残高切れ）。

- [ ] 有料モデルに変更するか残高を追加する。使わないならキーを消して
      パネルの選択肢から外す（`toggle.sh fishaudio-key clear`）

## 関連する実測値（Gemini）

チャンク分割も同日に実測して決めた。冒頭の無音は文字数を削っても縮まない
（固定の待ち時間が支配的）。

```
first=80  chunk_max=200 → 冒頭 12.8s  最小 slack -1.3  途切れ
first=40  chunk_max=200 → 冒頭  8.4s  最小 slack -4.7  悪化
first=70  chunk_max=260 → 冒頭 14.9s  最小 slack +4.4  余裕不足
first=110 chunk_max=260 → 冒頭 13.8s  最小 slack +9.2  採用
```

`CLOUD_FIRST_CHUNK_CHARS_GEMINI=110` / `CLOUD_CHUNK_CHARS_GEMINI=260`。
