長文読み上げのテスト運用で発生した問題（Gemini 429制限、フォールバック時の挙動、オフ設定の漏れ、終了音）の現状と対応策を整理した一覧です。

1. 外部TTS（Gemini等）失敗時にユーザーへ伝わらない
改修対応中
🔴 問題点
Gemini API の利用制限（HTTP 429）や混雑（503）が発生した際、ログに出力されるだけで、ユーザーの画面や通知バー、音声で状況が全く通知されず、突然機械音（ローカル音声）に変わるため原因不明に見えてしまう。
💡 対策・解決案
termux-notification を利用し、エラー発生時に Android 通知バーへ「⚠️ Gemini 429: 利用制限中。約2分間ローカルで読み上げます」と理由と復旧見込みを即時通知する。
2. ローカルへの切り替え後、音声が「細切れ」で途切れる
改修対応中
🔴 問題点
クラウド生成が失敗してローカル（Termux TTS）にフォールバックした際、分割された文を1文ずつループ再生していたため、「1文再生 → 数秒の沈黙 → 次の1文再生」と短くブツブツ途切れる最悪のUXになっていた。
💡 対策・解決案
クラウド失敗時は、残りの文（ユニット）をすべて一つの文章に再結合（join）し、1回のローカルTTSで最後まで一気にスムーズに読み上げる。
3. レート制限（429）中に無駄なAPI再試行を繰り返す
改修対応中
🔴 問題点
一度 429（制限超過）になってもクールダウン機構がないため、毎回失敗すると分かっているAPIを叩いて数秒待たされる無駄が発生していた。
💡 対策・解決案
サーキットブレーカーを導入。429発生時は「2分間クラウドAPIをスキップして即座にローカルで読み上げ」を行い、無駄な待機と通信を完全排除する。
4. 音声オフ時にも相槌音声（フィラー）が鳴ってしまう
✅ 修正完了
🔴 問題点
プレウォームされたフィラーを再生する際、停止スイッチのチェックを介さずに直接 termux-media-player を呼んでいたため、読み上げオフ時も相槌だけが鳴っていた。
💡 対策・修正内容
agy-summarize-and-speak.sh および agy-pre-warm.sh の最上部に停止スイッチ判定を配置し、オフ時はフィラー含め即座に完全沈黙するよう修正済み。
5. 終了時の音声（「またね」）が鳴らない
✅ 原因特定・パイプ修正済
🔴 問題点・原因
① 読み上げオフ時は安全のため終了音もミュートされる仕様。
② agy-session-end.sh で標準入力のパイプ渡しが抜けていた。
③ AGY（Antigravity CLI）のフック仕様（hooks.json）には現時点で SessionEnd イベントが存在しない。
💡 対策・対応内容
パイプの受け渡しは修正完了。Claude Code終了時や読み上げオン時は正常に鳴る状態。AGYでのセッション終了検知は将来のCLI機能拡張またはシェル監視で対応。
